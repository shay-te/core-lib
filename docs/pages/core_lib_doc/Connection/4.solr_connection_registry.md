`SolrConnectionFactory` creates one [pysolr](https://github.com/django-haystack/pysolr/){:target="_blank"} `Solr` client from config when it is built, and hands that same client to every `with solr.get() as client:` block. The `with` block does **not** close the client on exit.

**What it adds over pysolr:** very little. It builds the client from config and gives your `DataAccess` the same `.get()` shape as every other Core-Lib connection, so a test can pass in an [`ObjectConnectionFactory`](object_connection_factory.html) instead. Inside the block you use the normal pysolr API.

> **Where it fits:** Connection layer for Solr. Build it in `CoreLib.__init__`, pass it to your search `DataAccess` classes, and keep Solr queries out of `Service` classes.

## Example

### `your_core_lib.yaml`

```yaml
# @package _global_
core_lib:
  data:
    solr:
      always_commit: true
      url:
        protocol: http
        host: ${oc.env:SOLR_HOST}
        port: ${oc.env:SOLR_PORT}
        path: solr
        file: your_core
```

This builds `http://<host>:<port>/solr/your_core`. `protocol` is required in practice: without it the URL has no `http://` and every request fails. `always_commit: true` makes pysolr commit after every add and delete.

Unlike the other connection pages, this block has no `_target_`. Core-Lib's packaged defaults already declare `core_lib.data.solr` in this form (`always_commit: true`, `url: ~`). When your config composes those defaults, a `_target_` block at the same path is merged with their keys and fails to build. So you fill in `url` and call the constructor.

### `your_core_lib.py`

```python
from omegaconf import DictConfig

from core_lib.core_lib import CoreLib
from core_lib.connection.solr_connection_factory import SolrConnectionFactory

from your_core_lib.data_layers.data_access.user_search_data_access import UserSearchDataAccess
from your_core_lib.data_layers.service.user_search_service import UserSearchService


class YourCoreLib(CoreLib):
    def __init__(self, config: DictConfig):
        super().__init__()
        self.config = config
        solr = SolrConnectionFactory(self.config.core_lib.data.solr)
        self.user_search = UserSearchService(UserSearchDataAccess(solr))
```

### `user_search_data_access.py`

User input that goes into a Solr query string must be escaped, or a search for `x OR *:*` changes the query. pysolr has no helper for this, so the example escapes Solr's special characters itself.

```python
import re

from core_lib.connection.solr_connection_factory import SolrConnectionFactory
from core_lib.data_layers.data_access.data_access import DataAccess
from core_lib.error_handling.not_found_decorator import NotFoundErrorHandler

# Characters with a meaning in Solr query syntax. Escape them in user input.
SOLR_SPECIAL_CHARS = re.compile(r'([+\-&|!(){}\[\]^"~*?:\\/\s])')


class UserSearchDataAccess(DataAccess):

    def __init__(self, solr: SolrConnectionFactory):
        self._solr = solr

    def search_by_name(self, prefix: str, limit: int = 20) -> list:
        escaped = SOLR_SPECIAL_CHARS.sub(r'\\\1', prefix)
        with self._solr.get() as client:
            return list(client.search(f'name:{escaped}*', rows=limit))

    @NotFoundErrorHandler()
    def get(self, user_id: int) -> dict:
        with self._solr.get() as client:
            results = client.search('*:*', fq=f'user_id:{int(user_id)}', rows=1)
            return results.docs[0] if results.docs else None

    def delete(self, user_id: int):
        with self._solr.get() as client:
            client.delete(q=f'user_id:{int(user_id)}')
```

- `search_by_name('ja')` sends the query `name:ja*` and returns the matching documents as dicts.
- `get` returns one document. When there is none, `@NotFoundErrorHandler()` turns the `None` into a 404 `StatusCodeException` (see [Error Handling](error_handler.html)).
- `delete` uses pysolr's `delete(q=...)`, which deletes every document that matches the query.
