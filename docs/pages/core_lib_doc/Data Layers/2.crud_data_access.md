Writing `get`, `create`, `update`, and `delete` against every SQLAlchemy model is tedious and identical every time. Core-Lib provides three `CRUD` base classes — pick the one that matches how you want deletes to behave, then your `DataAccess` only defines what makes it different.

| Base class | Delete behavior | Use when |
|---|---|---|
| `CRUDDataAccess` | Hard delete (row is removed) | You don't need audit history |
| `CRUDSoftDeleteDataAccess` | Sets `deleted_at` timestamp | You want soft delete |
| `CRUDSoftDeleteWithTokenDataAccess` | Soft delete + indexed `deleted_at_token` | You query deleted rows often |

---

## Example — plain CRUD

```python
from sqlalchemy import Column, Integer, VARCHAR, Boolean
from core_lib.connection.sql_alchemy_connection_factory import SqlAlchemyConnectionFactory
from core_lib.data_layers.data.db.sqlalchemy.base import Base
from core_lib.data_layers.data_access.db.crud.crud_data_access import CRUDDataAccess


class Customer(Base):
    __tablename__ = 'customer'
    id = Column(Integer, primary_key=True)
    name = Column(VARCHAR(255), nullable=False)
    email = Column(VARCHAR(255), nullable=False)
    active = Column(Boolean, nullable=False)


class CustomerDataAccess(CRUDDataAccess):
    def __init__(self, db: SqlAlchemyConnectionFactory):
        super().__init__(Customer, db)
```

That's the whole `DataAccess`. `get`, `create`, `update`, and `delete` come from the base class:

```python
customer = CustomerDataAccess(db)
customer.create({'name': 'Jon Doe', 'email': 'jon@doe.com', 'active': True})
customer.update(1, {'email': 'jon.doe@example.com'})
customer.get(1)        # returns the Customer row
customer.delete(1)     # row is gone
customer.get(1)        # raises StatusCodeException (404)
```

## Example — soft delete with indexed token

Same `Customer` entity as the plain example above — only two lines change. The entity inherits two extra mixins, and the `DataAccess` extends a different base class:

```python
from core_lib.data_layers.data.db.sqlalchemy.mixins.soft_delete_mixin import SoftDeleteMixin
from core_lib.data_layers.data.db.sqlalchemy.mixins.soft_delete_token_mixin import SoftDeleteTokenMixin
from core_lib.data_layers.data_access.db.crud.crud_soft_delete_token_data_access import CRUDSoftDeleteWithTokenDataAccess


class Customer(Base, SoftDeleteMixin, SoftDeleteTokenMixin):   # + two mixins
    __tablename__ = 'customer'
    id = Column(Integer, primary_key=True)
    name = Column(VARCHAR(255), nullable=False)
    email = Column(VARCHAR(255), nullable=False)
    active = Column(Boolean, nullable=False)


class CustomerDataAccess(CRUDSoftDeleteWithTokenDataAccess):   # different base class
    def __init__(self, db: SqlAlchemyConnectionFactory):
        super().__init__(Customer, db)
```

`delete(1)` now sets `deleted_at` and `deleted_at_token` instead of removing the row.

## CRUD

*core_lib.data_layers.data_access.db.crud.CRUD* [[source]](https://github.com/shay-te/core-lib/blob/master/core_lib/data_layers/data_access/db/crud/crud.py#L7){:target="_blank"}

 `CRUD` is an abstract base class used by  `CRUDDataAccess`.
```python
class CRUD(ABC):

    def __init__(self, db_entity, db: SqlAlchemyConnectionFactory, rule_validator: RuleValidator = None):
        self._db_entity = db_entity
        self._db = db
        self._rule_validator = rule_validator
```

**Arguments**

- **`db_entity`**: The database entity used by this `DataAccess`.  
- **`db`** *`(SqlAlchemyConnectionFactory)`*: Instance of the `SqlAlchemyConnectionFactory` used to connect to the database.  
- **`rule_validator`** *`(RuleValidator)`*: Uses the `RuleValidator` instance to validate data passed into `create()` and `update()` methods (optional).

### CRUDSoftDeleteWithTokenDataAccess

*core_lib.data_layers.data_access.db.crud.CRUDSoftDeleteWithTokenDataAccess* [[source]](https://github.com/shay-te/core-lib/blob/master/core_lib/data_layers/data_access/db/crud/crud_soft_delete_token_data_access.py#L10){:target="_blank"}

This class is similar to `CRUDSoftDeleteDataAccess` but is uses `SoftDeleteMixin` as well as `SoftDeleteTokenMixin` which
creates the `deleted_at_token` column, because indexing a `DateTime` column is slow, adding the `deleted_at_token` allows us to index the columns that have been deleted.

```python
class CRUDSoftDeleteWithTokenDataAccess(DataAccess, CRUD):

    def __init__(self, db_entity, db: SqlAlchemyConnectionFactory, rule_validator: RuleValidator = None):
        CRUD.__init__(self, db_entity, db, rule_validator)
```
