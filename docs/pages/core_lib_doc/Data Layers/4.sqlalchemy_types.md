SQLAlchemy's built-in column types don't cover everything. Core-Lib ships two custom column types: `IntEnum` stores a Python enum as an integer, and `Point` is a spatial `POINT` column with static helpers that convert coordinates to and from WKT strings such as `'POINT(34.7818 32.0853)'`. Read the [`Point` limitation](#point) before you use it as a column type. Its helpers also work with a geoalchemy2 `Geometry('POINT')` column.

> **Where it fits:** Data entity support. Use these types inside SQLAlchemy models under `data_layers/data/db/`.

---

## IntEnum

*core_lib.data_layers.data.db.sqlalchemy.types.int_enum.IntEnum* [[source]](https://github.com/shay-te/core-lib/blob/master/core_lib/data_layers/data/db/sqlalchemy/types/int_enum.py){:target="_blank"}

Stores a Python `enum.Enum` as an integer in the database. On write, the enum member's `.value` is stored. On read, the integer is converted back to the enum member.

```python
class IntEnum(sa.types.TypeDecorator):
    impl = sa.Integer

    def __init__(self, enumtype, *args, **kwargs):
```

**Arguments**

- **`enumtype`**: The Python `enum.Enum` class to map to/from.

> **Start enum values at 1.** `IntEnum` treats `0` like `NULL`: a stored `0` is read back as `None`, and a Python `enum.IntEnum` member with value `0` is written as `NULL`. Also assign enum members, not plain integers: `User(role=1)` fails on insert with `sqlalchemy.exc.StatementError: (builtins.AttributeError) 'int' object has no attribute 'value'` (a `StatementError` that wraps the `AttributeError`, not an `AttributeError` itself).

### Usage

```python
import enum
from sqlalchemy import Column, Integer
from core_lib.data_layers.data.db.sqlalchemy.base import Base
from core_lib.data_layers.data.db.sqlalchemy.types.int_enum import IntEnum


class User(Base):
    __tablename__ = 'user'

    class Role(enum.Enum):
        ADMIN = 1
        EDITOR = 2
        VIEWER = 3

    class Status(enum.Enum):
        ACTIVE = 1
        INACTIVE = 2

    id = Column(Integer, primary_key=True, nullable=False)
    role = Column(IntEnum(Role), default=Role.VIEWER)
    status = Column(IntEnum(Status), default=Status.ACTIVE)
```

Writing and reading (`db` is a `SqlAlchemyConnectionFactory`):

```python
with db.get() as session:
    user = User(role=User.Role.ADMIN)
    session.add(user)
    session.flush()                  # assigns user.id
    user_id = user.id

with db.get() as session:
    user = session.get(User, user_id)
    print(user.role)                 # Role.ADMIN  (an enum member, not 1)
    print(user.role.value)           # 1
    print(user.role.name)            # ADMIN
    print(user.status)               # Status.ACTIVE  (the column default)
```

The row in the database holds `role = 1` and `status = 1`.

## Point

*core_lib.data_layers.data.db.sqlalchemy.types.point.Point* [[source]](https://github.com/shay-te/core-lib/blob/master/core_lib/data_layers/data/db/sqlalchemy/types/point.py){:target="_blank"}

A column type for a spatial `POINT` column. It does not convert dicts: you write a WKT string (build it with `Point.to_point_str()`) and read back a WKT string (parse it with `Point.from_point_str()`). The SQL it emits is a `POINT` column, writes wrapped in `ST_GeomFromText(...)`, and reads wrapped in `ST_AsText(...)`.

```python
class Point(UserDefinedType):
```

```python
from sqlalchemy import Column, Integer
from core_lib.data_layers.data.db.sqlalchemy.base import Base
from core_lib.data_layers.data.db.sqlalchemy.types.point import Point


class Location(Base):
    __tablename__ = 'location'

    id = Column(Integer, primary_key=True)
    coordinates = Column(Point())    # see the limitation below
```

> **Limitation: writing through a `Point()` column fails on the common databases.**
> - PostgreSQL with PostGIS: `POINT` creates PostgreSQL's built-in `point` type, not a PostGIS geometry, so the insert fails with `column "coordinates" is of type point but expression is of type geometry`.
> - MySQL: geoalchemy2 (installed with Core-Lib) compiles `ST_GeomFromText` for MySQL and expects the column type to have an `srid`. The insert fails before it reaches the database with `AttributeError: 'Point' object has no attribute 'srid'` (seen with geoalchemy2 0.20).
> - SQLite has no `ST_GeomFromText` or `ST_AsText`.
>
> Use a geoalchemy2 `Geometry('POINT')` column instead, with the static helpers below.

### With a geoalchemy2 `Geometry('POINT')` column

This runs on PostgreSQL with PostGIS:

```python
from sqlalchemy import Column, Integer
from geoalchemy2 import Geometry
from core_lib.data_layers.data.db.sqlalchemy.base import Base
from core_lib.data_layers.data.db.sqlalchemy.types.point import Point
from core_lib.data_transform.result_to_dict import result_to_dict


class Place(Base):
    __tablename__ = 'place'

    id = Column(Integer, primary_key=True)
    coordinates = Column(Geometry('POINT'))


with db.get() as session:
    place = Place(coordinates=Point.to_point_str(longitude=34.7818, latitude=32.0853))
    session.add(place)
    session.flush()
    place_id = place.id

with db.get() as session:
    place = session.get(Place, place_id)
    print(Point.from_point_wkb(place.coordinates))   # {'latitude': 32.0853, 'longitude': 34.7818}
    print(result_to_dict(place))                     # {'id': 1, 'coordinates': {'latitude': 32.0853, 'longitude': 34.7818}}
```

geoalchemy2 returns the column as a `WKBElement`. `result_to_dict` (and so `@ResultToDict()`) converts it to a `{'latitude': ..., 'longitude': ...}` dict for you.

### Static methods

#### `to_point_str()`

Builds a WKT `POINT` string from longitude and latitude, for writing to the database.

```python
@staticmethod
def to_point_str(longitude: float, latitude: float, latitude_first: bool = False) -> str:
```

**Arguments**

- **`longitude`** *`(float)`*: Longitude value.
- **`latitude`** *`(float)`*: Latitude value.
- **`latitude_first`** *`(bool)`*: Default `False`. When `True`, emits `POINT(lat lon)` instead of `POINT(lon lat)`.

**Example**

```python
from core_lib.data_layers.data.db.sqlalchemy.types.point import Point

point_str = Point.to_point_str(longitude=34.7818, latitude=32.0853)
# 'POINT(34.7818 32.0853)'
```

#### `from_point_str()`

Parses a WKT `POINT` string, such as the value `ST_AsText()` returns, into a dict.

```python
@staticmethod
def from_point_str(point_str: str, latitude_first: bool = False) -> dict:
```

**Arguments**

- **`point_str`** *`(str)`*: WKT `POINT` string, e.g. `'POINT(34.7818 32.0853)'`.
- **`latitude_first`** *`(bool)`*: Default `False`. Set to `True` if the string has latitude first.

**Returns**

*`(dict)`*: `{'longitude': float, 'latitude': float}`.

**Example**

```python
location = Point.from_point_str('POINT(34.7818 32.0853)')
# {'longitude': 34.7818, 'latitude': 32.0853}
```

#### `from_point_wkb()`

Converts a geoalchemy2 `WKBElement`, which is what a `Geometry('POINT')` column returns, to a dict. It does not accept a WKT string: use `from_point_str()` for those.

```python
@staticmethod
def from_point_wkb(point) -> dict:
```

**Arguments**

- **`point`**: A geoalchemy2 `WKBElement` (or `WKTElement`) holding a point.

**Returns**

*`(dict)`*: `{'latitude': float, 'longitude': float}`.

See the `Geometry('POINT')` example above.
